| Decision needed | Agent stakeholder | Rahul's comments |

| **Attention weight data.** Each token-pair connection must have a hand-authored weight (0–1 or 0–100). These weights ARE the level — the distribution shape, the peaks, the aha all depend on them. Who authors these, and what is the scale? | lead-programmer | |
| **Completion condition.** There is currently no completion state. Options: player presses "I see it" after any interaction, game gates on the slider crossing a specific range, player must identify the two high-weight connections before advancing. Which? | lead-programmer, game-designer, ux-designer | |
| **What prevents a two-second slider drag and advance?** If the player can sweep the slider from 0 to max and back in three seconds then proceed, the level teaches nothing. What is the gating condition — minimum dwell, must observe a specific state, must answer a prompt? | game-designer | |
| **Starting state of connections.** Before the player touches the slider, are all connection bars already visible at full opacity (filtering model) or hidden and revealed as the slider lowers (discovery model)? These produce different discovery dynamics. | ux-designer | |
| **Threshold transition — sharp or smooth.** As the slider crosses a connection's weight, does it switch binary on/off or fade smoothly? Smooth better encodes that attention is continuous; binary risks teaching it as a threshold filter. | ux-designer | |
| **Target token selection — pre-set or player-chosen.** Is the target token always pre-highlighted at level start, or does the player select it by tapping? If player-selects, what happens when they look at a non-ambiguous token and see a flat distribution? | game-designer, ux-designer | |

| **Desktop hover vs. mobile tap for token highlight.** On desktop, hovering a token could show its connection weights. On mobile there is no hover. Is the target token always fixed at level start, or is there a tap-to-select interaction that works on both platforms? | ux-designer | |

## Level 4 — The Town Square

| Decision needed | Agent stakeholder | Rahul's comments |
|---|---|---|
| **Distribution→synthesis mapping function.** 10 chips over 5 citizens yields ~1000 distinct distributions; only 8–10 synthesis variants exist. How does an arbitrary player distribution map to a variant — nearest-neighbour, dominant-citizen bucket, constrained input that only allows N configurations? This is an unsolved logic decision the spec filed under "content to write." | lead-programmer, game-designer | |
| **Pre-configured examples — before or after the player's own allocation?** Do the two example distributions appear first (player sees how it works, then tries), or after the player's first attempt (player commits blind, then sees comparison)? Pedagogical sequence determines whether this is discovery or answer-reveal. | game-designer | |
| **All-or-nothing distribution — valid completion?** If the player puts all 10 chips on one citizen and 0 on the rest: is this a valid commit? If yes, a synthesis variant must exist for it. If yes and it produces a synthesis, what prevents this from being the default shortcut? | game-designer, lead-programmer | |
| **Chip redistribution before commit.** Can a player remove a chip from a citizen and reassign it before committing? If not, mobile misclicks become irreversible. If yes, what does "remove chip from citizen" look like as an interaction? | lead-programmer, ux-designer | |
| **Synthesis update timing — real-time or on commit.** Does the synthesis text update live as chips are moved, or only after the player commits? Real-time better shows the causal relationship between weights and synthesis; on-commit creates more of a "reveal" moment. | lead-programmer | |
| **Chip allocation input on mobile.** Drag chips from a pool (precise but risks scroll conflict) vs. tap-to-increment on each citizen card (safe but less physical). Which model? | ux-designer | |
| **Chip pool starting state.** Do all 10 chips start in a pool (player allocates from zero), distributed equally (2 per citizen), or all on the first citizen? Each creates different cognitive framing. | ux-designer | |
| **Citizen card content budget.** Each citizen "speaks about a situation." At 5 cards on a mobile screen, how many words of text can each card show? One sentence? A name plus a short quote? This determines how much narrative context the player has while allocating. | ux-designer | |

## Level 7 — The Tower

| Decision needed | Agent stakeholder | Rahul's comments |
|---|---|---|
| **What prevents click-click-click-done?** Nothing in the spec creates friction against rapid clicking through all layers. Options: enforced dwell time per layer, "add layer" button disabled until the player interacts with or names the current state, a required identify-what-changed prompt between layers. | game-designer, ux-designer | |
| **Completion gating — layer count or resolution state?** Can the player stop at Layer 1 or 2 and advance? Or must they reach Layer 3 (full resolution) before the exit is available? | lead-programmer, game-designer | |
| **Is the remove-and-restore action required for completion?** The insight ("you needed all three passes") depends on the player having removed a layer and felt the regression. If the player only adds layers and never removes, they see the resolution but don't feel the dependency. Does the level gate on the remove action occurring? | game-designer, ux-designer | |
| **Token state visual encoding per layer.** The four resolution states (unresolved, local context, weighted lean, settled) are written as narrative text labels. What is their visual encoding — confidence bars for two referents, colour coding, the alternate referent graying out? The distinction between "weighted lean" (Layer 2) and "settled" (Layer 3) must be visually legible. | ux-designer | |
| **Tower visual metaphor on mobile.** A tower growing vertically has layout challenges in portrait orientation. Does the tower grow upward (requiring scroll as it grows), or is each layer shown as a horizontal step, or does a fixed-height container replace completed layer states? | ux-designer | |
| **Remove-layer animation.** Does the tower shrink visually when a layer is removed, and does the token state animate back to its previous form or snap instantly? The regression animation is the level's most pedagogically important visual. | ux-designer | |
| **Dwell time per layer.** After adding a layer and before the "add layer" button reactivates, is there a minimum display time — and how long? Without enforced dwell, the resolution progression doesn't register. | game-designer | |

## Level 8 — The Oracle

| Decision needed | Agent stakeholder | Rahul's comments |
|---|---|---|
| **Oracle probability distribution data.** The "right" distribution the player is compared against must be hand-authored for each practice context and for the final sentence. These are numerical values, not copy. Who authors them? | lead-programmer | |
| **Calibration/scoring function.** "Player sees where they were calibrated and where they were overconfident" requires a defined scoring function — distance between distributions, cross-entropy, per-candidate delta? Without this, there is no feedback to render. | lead-programmer, game-designer | |
| **Calibration feedback visual.** How is calibrated vs. overconfident shown — colour-coded bars (green = close, red = far), numeric delta labels, a diff overlay, a scatter view? The visual encoding shapes whether the player understands calibration as a concept or just sees "I was wrong." | game-designer, ux-designer | |
| **No-right-answer framing.** Showing the player's distribution next to the Oracle's will feel evaluative — the player reads it as score vs. not-score. What copy and visual language prevents the "I was wrong" read and reinforces "I was appropriately calibrated or overconfident"? | ux-designer, game-designer | |
| **Gated ending condition.** What counts as completing the mechanic to unlock the final beat — any committed distribution, nonzero values on at least N candidates, or calibration within a tolerance? | game-designer, lead-programmer | |
| **100-point budget enforcement.** If a player has allocated 90 points and tries to allocate 20 more, what happens — input blocked, excess auto-deducted from another candidate, or a zero-sum slider gang? The enforcement UI pattern needs specifying. | ux-designer | |
| **Practice round count.** How many practice-and-compare cycles before the final Oracle sentence appears? Too few: the mechanic is unfamiliar at the climax. Too many: the ending is diluted. | game-designer | |
| **Oracle's final sentence.** Not yet written. Must be genuinely ambiguous with 3–5 plausible completions, and the highest-probability draw must produce a sentence that "sounds right" regardless of which candidate is selected. Has a candidate sentence been attempted? | game-designer | |
| **"City erupts" visual event.** What does the climax look like as an interface event — screen animation, text completing itself, sound, confetti, the Oracle sentence filling in? This is the game's entire payoff and currently unspecified. | ux-designer | |
| **Final sentence interaction — same or ceremonial.** Does the player use the same distribution UI for the final Oracle sentence as for practice examples, or does the climactic moment use a different, more ceremonial interaction pattern? | ux-designer | |
| **Oracle reveal animation.** After the player commits, how does the Oracle's distribution appear — bars animating in, overlay on top of the player's, player's bars transitioning to the Oracle's? | ux-designer | |
